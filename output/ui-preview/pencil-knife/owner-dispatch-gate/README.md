# Native Knife owner and queued-action gate

63 tests pass at both O0 and O2 against the current materialized candidate.
This contains 59 compiled runtime cases and four source guards. The report
records exact input hashes. The test reads source at each process invocation;
use `--source-root` until the candidate is integrated into the canonical patch.

The actual native functions bind only after list insertion, capture fresh
registered operator/type/ID/context values without provider callbacks, distinguish
presentation presence from strict input eligibility, queue one copied value
request from a release UI scope and resolve the original live handler again.
The real dedicated native UI handler predicate also executes. Missing saved
ViewLayer refuses with zero fallback provider callbacks; stale or unrelated
operator/type/ID/window/handler/UI inputs refuse. Poison numeric operator and
handler addresses are used to verify refusal before unsafe reads.

A private-action-only adapter executes the genuine WM request prefix, original
context setup, semantic action branch, undo-depth bookkeeping and full native
window/status cleanup block. FINISHED and CANCELLED take distinct native branches.
The UI callback boundary never calls Knife. Queued finish can run after the
native button was destroyed while its deferred-free UI handler remains inert.

Initial registration, presentation/contact acquisition, lists, allocator and
registry/BKE/UI lookup primitives, event scheduling, ED native action and
operator/handler free/finished effects are explicitly modeled. Full WM scheduler,
geometry, history, UIKit and device acceptance are not proved. Source model
results do not authorize a package-ready claim by themselves.
