# Read-only Pencil Knife PAN origin contract

Scope is exact overlay40533b99 while the current paint package gate runs. This is a next-design candidate, separate from the already proved Ctrl-Knife zoom case and from paint contact ownership. No source, test, UI or build changes were made.

## Recommendation

Use a dedicated value-only physical-origin **suppression hint**, not existing `ToolManipulation`. Its only effect is to omit this recognizer contact's paired `PAN_GESTURE`. Keep the actual precision event sequence: Began cursor/down at its current recognized location; Changed optional PAN before cursor; terminal up without an added cursor. Keep every current cached-translation update, tablet sample, native modifier, cancellation flag and packet order. For admitted Knife contacts only, remove the optional paired PAN. There is no native modal ownership claim and no new terminal/lease/Cancel behavior.

Routing through current `PointerCapture` is materially different: Began queues origin cursor/down, then another current cursor; terminal queues cursor then up; `ToolManipulation` also sets direct_tool. Knife's ADD_CUT/mousemove/freehand drag-hold depends on those positions and ordering. That path cannot be used as an implementation shortcut for PAN omission.

## What the actual source provides

* `GHOST_NavigationIOS.hh`: `NavigationRect` is bounds/kind/direct_selection/HUD generation. Generic rectangles have no tool/mode/window lifetime or presentation generation. `pointer_capture_hit` is first-hit and `PointerCapture` stores only kind/ended; finish() is one-release arithmetic, not an enqueue acknowledgement or native operator lease. `forget_navigation_window` erases existing registries on GHOST destruction.
* `GHOSTUIPanGestureRecognizer`: `touchesBegan` freezes device/physical identity/serial, ring, HUD and paint before calling superclass; `touchesEnded/Cancelled` retain contact through superclass action delivery; reset clears values. `handlePan` generic hit testing happens later at recognizer Began after threshold. A Knife hint belongs at physical touchesBegan, not that later hit lookup.
* `wm_draw.cc`: the generic navigation/tool map is assembled near the end of onscreen drawing using current native tool and `ED_ipad_editing_canvas_parts`; popup presence clears it. It only publishes ToolManipulation for shared `direct_edit_tool`. This is a useful geometry seam, but its unversioned map alone cannot establish delayed physical-origin freshness.
* The paint presentation pipeline is stronger: before/after actual region draw, buffer receipt, successful actual blit/composition recording, higher-region blockers and end-of-compositor publication. Its paint eligibility cannot be copied: `wm_ipad_finger_paint_publish` rejects modifiers/keymodifier and all UI/OP modal handlers. Native Knife Ctrl/Shift and subsequent multicut contacts while its modal remains alive must remain usable.
* `ED_ipad_editing_canvas_parts` subtracts the presented editing shelf from `ipad_canvas_rect`; that rectangle originates in panel layout. It does not by itself prove a successful current buffer blit or subtract every higher composited region/opaque callback. Reuse the arithmetic, not an unsupported complete-presentation claim.

## Minimal value data

Native private last-presented state needs an exact Knife/Edit Mesh eligibility kind, viewport identity-as-token, screen UID/window identity, region geometry, native window dimensions/scale and exposed parts. Use a nonzero monotonically unique presentation epoch (no address-only identity; overflow refuses). Keep an epoch stable only across a contiguous sequence of identical eligible semantic owner/geometry presentations, or explicitly record continuity. Any absent/ineligible frame or changed owner/geometry gets a new epoch; A→B→A must not revive A's old epoch. Do not tie eligibility to Ctrl/Shift bits, Knife snap flags or absence of an ordinary Knife OP handler.

GHOST stores only registry values keyed by window handle. A contact hint is epoch + existing physical Pencil serial + origin x/y + Knife kind. No Object/Mesh/BMesh/tool/operator pointer crosses the boundary. Region-address tokens, if used, are compared only with a fresh native membership walk and the globally unique epoch; never dereferenced after a callback. No mesh-storage identity family is required: this hint controls paired navigation emission, not the cut's geometry owner.

## Completed presentation admission

Candidate implementation seams are the actual `wm_draw_area_offscreen` before/after full-draw checks, `wmDrawBuffer` receipt, `wm_draw_window_area_layer` successful-blit record and `wm_draw_window_onscreen` final publish. Stamp only a stable native `SPACE_VIEW3D` / `EDIT_MESH` / `builtin.knife` WINDOW canvas. Reacquire native screen/area/region membership after drawing callbacks, validate original window/screen identity, dimensions/scale/region/canvas bounds and exact tool/mode; do not retain native pointers across drawing.

Only successful actually composited regions contribute. Reuse the actual higher-region order/blocker footprint recording and existing shelf/navigation/HUD exclusion. Any unknown opaque window callback or unproved visible popup/menu/dismissal surface declines the hint. Native modal Knife alone is allowed; UI handlers and unrelated modal interference require an explicit admission decision, not blanket acceptance or paint's blanket OP ban. A cached buffer requires a valid current geometry/context receipt; stale/unproved/partial-only presentation does not acquire a new Knife hint.

No generic `NavigationRect` behavior or `direct_edit_tool` whitelist changes are needed. Keep ordinary finger scrolling and indirect/trackpad/navigation paths exact.

## Physical freeze, liveness and retirement

1. Before superclass `touchesBegan`, consider only one actual Pencil touch on the current owning view with a fresh physical serial. Ring/HUD/navigation/resize/covered UI keep priority. Query a valid completed Knife presentation at that original physical point. An absent hint leaves all legacy behavior exact.
2. Before the first recognized Began can latch suppression, require that frozen epoch still belongs to the same contiguous eligible presentation and no native invalidation occurred. Do not recompute a different origin, retarget to a new tool, or turn an expired hint into a new Knife admission. If stale, simply decline PAN suppression while preserving the current precision sequence; do not quarantine/drop cursor/button packets as part of this change.
3. Once Began admits it, retain the omission decision for that one physical contact. Motion leaving the canvas is not a fresh UI-scroll gesture. Redraw must not resurrect/retarget the contact. Keep native cursor/down/up and independent navigation untouched; no fresh PAN is emitted simply because a later frame's hint expires.
4. Clear pending hint/latched suppression on reset and physical-stream invalidation. Honor the existing early hardware-drag suppression and ring paths. Destruction erases its registry before native handles are released; stale retained recognizers must fail lookup before any window dereference. Do not reuse epochs after address reuse.
5. Modifier keys during the existing cut must retain native delivery and must not retire an already admitted omission latch. Fresh acquisition with modifiers must remain possible after a valid eligible presentation. Copying the keyboard paint-region clear/modifier ban would defeat this contract.

A versioned last-frame registry does not alone prove step2 against native tool/screen/layout/popup changes that precede the next redraw. The implementation must identify and cover those invalidation points, or carry an origin hint to a native point that can validate fresh actual context before suppressing its specifically paired PAN. `WM_toolsystem_ref_set_from_runtime` is the actual central tool mutation seam (`ref_set_by_id_ex` calls the Python tool operator). Window scene/workspace/screen setters are concrete context seams; popup/region/layout changes and redraw callbacks must also be bounded. Do not infer every route is covered by naming those functions. This lifecycle proof is an explicit preimplementation gate. Broad global storage guards are not warranted.

## Knife lifecycle boundaries

* A normal up maps to native ADD_CUT release: clears is_drag_hold/ignore_edge_snapping, refreshes current hit, and keeps the modal running. New contact means a new hint, even though the same native Knife operator remains. No synthetic Enter/confirm on lift.
* Native Ctrl ignore-snap and Shift midpoint transitions remain exact. Ctrl may be pressed after the initial unmodified down (the confirmed failure). Initial Ctrl-down must keep normal native tool keymap behavior; this hint must not force Knife invocation through a modifier mismatch.
* Enter/NumEnter/Space confirms with native finish/exit and normal WM registration/Undo; Escape cancels through native exit. Preserve actual hardware events, including the existing secondary-window Escape-close behavior. Suppression survives only until that physical contact resets and does not promise the operator remains alive.
* A Pencil Cancelled/Failed precision callback currently sends an ordinary up for untagged Knife, without paint's cancelled flag. Knife itself does not inspect POINTER_CANCEL. This proposal leaves that native behavior exact and claims no interruption rollback.
* `cancelPointerCapture` currently sends terminals for an enqueued paint press or active generic PointerCapture, then invalidates recognizers. Untagged precision Knife has neither record. Thus a two-finger/hardware/deactivation interruption can invalidate it without this helper proving an exact Knife down/up pair. Suppression-only does not repair or certify that inherited terminal gap. Do not solve it by adopting ToolManipulation, inventing a terminal lease, sending an unleased up, Escape, or cancelling a replacement operator. A separately reproduced terminal change would require its own bounded contract.
